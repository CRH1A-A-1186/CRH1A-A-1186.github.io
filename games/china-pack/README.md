# 中国省份游戏 (China Province Pack)

把 34 个省级行政区投进箱子里的物理拼图，**相邻的省份碰到一起就会连成一片**，
摇一摇可以把积压的省份抖开，任何一块冒出箱口就结束。
把 34 个省级行政区连成一整幅中国地图，就进入下一局。

移植自 **[都道府県ゲーム (pref-pack)](https://sns.dopagamelab.com/pref-pack/)** —— 那个把 47 个都道府县
装进箱子的日本版小游戏。原版的玩法、物理参数、尺寸模型、结算演出全部保留，只是把
日本列岛换成了中国地图，界面换成中文。

一局发 **30 块**（不是 34 块）：**京津冀**（北京+天津+河北）和**粤港澳**（广东+香港+澳门）
开局就是连在一起的一整块，原因见下面「为什么这两组要合并」。

## 玩

直接打开 **`index.html`** 即可（纯静态，`file://` 也能跑，不需要服务器、不联网）。

- 在箱子里左右移动鼠标/手指瞄准，**松手投放**；指针停在箱口上方的留白处松手不会投放。
- 相邻的两个省真的碰到一起时才会连成一块，所以尽量把邻省放在一起。
- 「**摇一摇**」把箱内所有方块弹起、晃动箱子，可以让卡住的省份重新落位；摇动过程中不会判定溢出。
- 任何一块冒出箱口就结束。30 块全部投放后会出现倒计时，时间用完还没连成整幅地图也结束。
- 「**重开一局**」要按两次（第二次在 3 秒内按下）才会真的重开，避免误触。

计分：两块合并得 `(省份数)² × 10` 分；每连成一个完整的大区额外加分；全部投放 +1,000；
拼成整幅中国地图 +10,000。

## 为什么这两组要合并

游戏里两个方块能合并的条件是**同时**满足「两省相邻」和「两块真的碰到一起」。
中国有四个省通往全国的路特别窄：

| 省 | 邻居 | 问题 |
| --- | --- | --- |
| 北京、天津 | 只有彼此 + 河北 | 这一对加起来也只接河北，**河北是唯一出口** |
| 香港、澳门 | 只有广东 | 广东是唯一出口 |

它们又都在版图里面，不像海南、台湾那样能挪到一边去。所以会出现这样的死局：
如果山东、河北、辽宁、内蒙古先掉落并且连成一片，河北就被自己的其他邻居围住、埋进箱子底下；
之后掉下来的天津和北京**碰不到河北也碰不到任何能连的省**，两块永远进不去，
整幅地图在物理上就不可能拼成了。

最直接的修法是让这些省**不要单独发牌**：京津冀从第一手起就是一整块，粤港澳也是。
引擎本来就支持多省方块（合并时生成的就是这种），所以这只是把它们放进开局牌堆而已。
这样「只有一个出口」的省从一开始就已经连在出口上，不存在落单的可能。

两块都不大（京津冀 46×60、粤港澳 62×54 世界单位，箱体是 300×372），比单独一块河北
（48×61）还紧凑，所以没有挤压玩法空间。副产物是开局就领先 2 个省的进度，
实测最大连片从 15~16 省提高到 22 省。

其余省级行政区的邻居数都 ≥ 2，而且低度数的那两个（黑龙江 2 个、上海 2 个）**邻居彼此也相邻**，
埋掉一个还有另一个可碰，不构成单出口死路。

需要 Node.js。所有命令都在 `china-pack/` 目录下执行：

```bash

node tools/emit-data.mjs     # → src/pack-data.js
```


## 数据是怎么来的

**边界**：`data/sources/datav-provinces.json` 是 DataV.GeoAtlas 的省级边界（GeoJSON，34 个省级
行政区 + 一条南海诸岛附属要素）。`build-pack.mjs` 会丢掉那条附属要素，只保留每个省的主陆地和
**离主陆地 450 km 以内、面积 ≥ 400 km² 的岛屿**——海南那一条里带着一直到 7°N 的南沙岛礁，
不过滤掉的话这一个方块的包围盒会被拉长约 1500 km。

**面积**是球面多边形面积，和官方公布的数字对得上（新疆 163 万、西藏 120 万、内蒙古 114 万 km²…）。
面积决定方块在屏幕上的大小：`边长 ∝ 面积^0.28`（原版日本用 0.35；中国省级面积跨度比日本大得多，
指数调小一点，否则新疆、内蒙古会撑满箱体）。澳门只有 46 km²，另外设了最小边长，不然看不见。

**坐标系**是等距圆柱投影，单位公里，y 轴向南——和原版日本包同一个框架，所以游戏的物理、
尺寸模型、布局常量可以整段沿用：

```
x = 经度 × (6371·π/180) × cos(36.89°)
y = −纬度 × (6371·π/180)
```

**相邻关系**不是手写的，是从边界几何推出来的：相邻两省的边界折点必然重合（或相距几百米
以内），所以把所有边界顶点扔进 0.01° 的空间网格，凡是两省各有顶点落在彼此 500 m 以内、
且这样的顶点至少 4 组的，就判定为相邻。这样得到 70 对陆路相邻关系，逐个核对过：
北京↔天津↔河北、广东↔香港↔澳门、新疆↔西藏等等都对。

### 隔海相望也算相邻

上面这套只找得到**共享边界线**的省份。海南和台湾是岛，一条陆路边界都没有，所以邻居数是
**0**——把台湾丢在福建上、海南丢在广东上什么都不会发生。在玩家看来「隔着海峡面对面」
和「挨着」是同一回事，所以地图上明摆着的几条跨海关系在 `build-pack.mjs` 里作为正式邻接加入：

| 跨海 | 实测最近距离 |
| --- | --- |
| 海南 – 广东（琼州海峡，雷州半岛↔海南岛北岸） | 16 km |
| 山东 – 辽宁（渤海海峡，蓬莱↔旅顺） | 102 km |
| 台湾 – 福建（台湾海峡最窄处，平潭↔新竹） | 124 km |
| 海南 – 广西（北部湾） | 158 km |
| 台湾 – 广东（海峡南口，给台湾第二条路） | 294 km |

判据是「两省最近处 < 一个台湾海峡」，不是「是不是同一个海」。山东–辽宁 隔渤海海峡相望，
比台湾海峡还近，一开始以「不同海域」为由没收录，那个理由站不住，后来补上了。

每条加入时都会**重新测一遍距离并打印**，所以换数据源时这些数字不会悄悄失真。
最终邻接表 75 对。

### 岛就待在它真实的位置上

原版日本把冲绳平移到西南角、和本土分开摆。我一开始照搬了这个做法，把海南、台湾平移
到大陆以东的紧凑一列——结果发现**这会让它们永远合不起来**：每个方块的屏幕坐标都来自
这一套共享的公里坐标系，把岛挪开一千公里，就等于把它的几何也从邻居身边挪开了一千公里，
两个方块落在屏幕同一处时，它们的实际轮廓根本碰不到。

所以岛保留真实地理位置（海南就在广东南边，台湾就在福建东边），整幅图 5478 × 3938 km，
仍然塞得进箱子。`build-pack.mjs --shift-islands` 可以切回那套"整齐但合不起来"的摆法做对比，
并且构建时会自动检查每对「重心距离 < 两块半宽之和」，不满足就直接报出来。

### 窄路省份要等伙伴落地

海南通往全国基本只有广东这一条路（台湾有福建、广东两条）。要是广东先被别的省围住、
埋到箱子底下，后掉下来的海南照样会卡死。所以这类"窄路"的**单省方块**会等伙伴先落地：
伙伴已经在箱内、而且还有露在外面的边时才发牌。伙伴落地后玩家看得见、能主动去碰，
这条规则只是保证它不会来得太晚（团体方块——京津冀、粤港澳——本身就连在一起，不受影响）。

大区划分用的是常规七大区，另外把香港、澳门并入中南地区（它们只和广东接壤，单独成区的话
这一组不是连通的一片）。海南、台湾各自单独成一个大区，只提供颜色，不算可完成的大区
——对应原版北海道的处理。

## 难度

34 个省级行政区的**包围盒面积之和约为箱体面积的 1.5 倍**，而且中国省级面积跨度极大，
所以「一局之内把 34 个省连成一整幅地图」是**稀有成就**，不是常规流程——原版日本也是这个定位。
常规一局的节奏是：投放 → 靠合并腾地方 → 连成几个大区拿分 → 最后几块投放后进入倒计时。

### 方块大小：单省和合并块分开配

尺寸公式是 `边长 ∝ 面积^指数 ÷ √投影面积`。原版日本只有一个指数，但中国省级面积跨度
（澳门 46 km² ~ 新疆 163 万 km²）比日本大得多，一个指数调不动两头，而且会撞上一个
**饱和效应**：

> 12 个省之后继续合并，方块几乎不再变大。省份挤进紧凑的合并块后，投影面积增长比真实面积更快，
> 把缩放因子压了回去。实测 12 省 → 28 省，真实面积 +76%，投影只 +37%。

饱和的后果是终盘箱子一直是空的——最高的一块离箱口还有 55 单位，剩下的碎片随便扔都放得下，
难度在最需要压力的时候消失了。

所以拆成两个旋钮：

| 旋钮 | 作用 | 当前值 |
| --- | --- | --- |
| `SIZE_EXP` | 单省方块，也决定各省之间的大小差距 | 0.28 |
| `MERGE_EXP` | **只**影响合并块（指数作用在成员面积之和上） | 0.32 |
| `PIECE_SCALE` | 整体缩放（前期拥挤程度） | 0.92 |

`verify-testmode.mjs` 会验证这两个旋钮确实解耦：改 `MERGE_EXP` 时单省宽度一个像素都不变，
而 20 省合并块宽度 +24%。

用 `tools/tune-final.mjs` 每组跑 24 局选出来的结果：

| 设置 | 箱子填充 | 平均最大连片 | 溢出结束 |
| --- | --- | --- | --- |
| 旧（单指数 0.28，scale 0.88） | 29% | 8.8 省 | **8%** ← 终盘几乎零压力 |
| **现在（mergeExp 0.32，scale 0.92）** | **35%** | **8.3 省** | **42%** |
| 更狠（mergeExp 0.32，scale 0.95） | 39% | 7.8 省 | 58% |

注意「平均最大连片」反而变小了，这正是想要的效果：该连的大块变大了、剩下的碎片少了，
而不是到处散着许多小块。48 局压测的结束方式也从 2 次溢出/46 次倒计时变成 **20/28**——
终盘终于有压力了。

### 测试模式：只发能接上的方块

随机发牌下，连成 20 多个省已经很靠运气，所以**「34 省连成一整幅地图」这个完成条件一直没被验证过**。
`drawFromDeck()` 里有一个测试模式开关，打开后每一手都从"还能和箱内拼上"的方块里挑，
并且优先挑邻居最多的那块；牌堆快空、剩下的都接不上时自动放宽，保证 30 块一定发得完。
正常游戏完全不受影响。

```js
window.__cnPack.setOrderedDeal(true);   // 只在控制台/测试脚本里用
```

`tools/verify-winnable.mjs` 用它跑一局：机器人在箱内找一个自己接壤的省，把方块精确摆到
"靠着它"的位置（用游戏自己的碰撞检测确认没有互相插入），然后看这条链能长到多大。
实测可以稳定连到 **21~22 个省**；剩下几块不是没地方放，而是接不上已经连成的大块了。
0.95 那档更挤、更难，但连片反而更小——所以最终选了中间那组。

## 跑测试

用一条命令并行跑完所有校验（每个校验是独立进程，只读打包好的 `game.js`）：

```bash
node tools/test-all.mjs            # 默认：完整扫描，约 3.5 分钟
node tools/test-all.mjs --quick    # 抽样快跑，约 1 分钟（日常改动用这个）
node tools/test-all.mjs --full     # 加大样本（压力测试 100 局/策略），约 3.5 分钟
node tools/test-all.mjs --only=verify,verify-islands     # 只跑其中几个
```

`--quick` / `--full` 会传给每个校验脚本，它们各自把"局数 / 扫描步长 / 落点采样"调大调小。

### 为什么以前那么慢，以及改了什么

先用 `tools/bench.mjs` 量了一遍，找到三个真正的瓶颈：

| 瓶颈 | 原因 | 改进 |
| --- | --- | --- |
| `collisionAt()` 0.46 ms/次 | 每次调用都 `createBody()`，等于把合并块**重新凸分解一遍**；而二分找落点会调用上千次 | 复用一个临时刚体，只在换方块时重建 → **0.046 ms，快 10 倍** |
| `buildPiece()` 7.5 ms/次（21 省合并块） | 每次合并都重算，但离线测试里同一组合会被反复构造 | 按「省份组合 + 角度 + 尺寸版本」缓存 → **0.31 ms，快 24 倍** |
| 8 个校验脚本串行跑 | 它们互不依赖 | `test-all.mjs` 并行启动 → 墙钟时间约为其中最慢的一个 |

改完之后（本机 20 核）：

| | 之前 | 现在 |
| --- | --- | --- |
| `verify-islands` 单项 | 213 s | 46 s（快跑）/ 203 s（全扫） |
| 全部 8 项 | 约 10 分钟（串行相加） | **54 s（--quick）/ 218 s（默认）** |

物理本身仍是主要成本（合并到 20 多省时每个 `step()` 约 0.3 ms，一局几百到几千步），
这部分没法绕过——它就是被测对象。能省的是"测试脚手架"的开销，上面三项都是这一类。

`tools/bench.mjs` 可以随时重跑看当前的开销分布。

## 分享与署名

**分享走微博。** 原版分享到 X，但大陆访问不了推特，所以按钮改成微博的网页分享入口
（`service.weibo.com/share/share.php`，实测返回「分享到微博」页面）。三种情况分别处理：

1. 手机上系统分享面板可用（还能把成绩图一起发出去）→ `navigator.share`，体验最好
2. 网页应用壳（iOS App）→ 交给壳自己弹分享
3. 其它情况 → 成绩**复制到剪贴板**并弹提示，同时链接打开微博发布页

两个细节：

- 链接在**结算界面出现时就填好**，不是等点击才填——否则按钮在悬停提示/右键菜单里显示的还是 `#`。
- `navigator.clipboard` 需要安全上下文，从 `file://` 直接打开时它是 undefined，所以还有一条
  `document.execCommand('copy')` 的兜底路径。
- 按钮图标是通用的分享符号，不是推特的 X logo（原版用的是 X logo）。

**署名**写在开始界面和结算界面的卡片里：

```
移植自 都道府県ゲーム (pref-pack) · by dopagamelab
物理引擎 matter-js · 省级边界 DataV.GeoAtlas
```

## 排列与发牌的几个坑

移植过程中踩到的、都已在 `tools/` 里加回归测试的坑：

| 现象 | 根因 | 现在的做法 |
| --- | --- | --- |
| 京津冀/粤港澳永远连不起来 | 这些省通往全国只有一条路，主体省被埋住就成死局 | 这两组开局就是**一整块**（`DEAL_GROUPS`） |
| 台湾丢在福建上、海南丢在广东上没反应 | 岛没有陆路边界，邻接表里邻居数是 0 | 跨海峡也算相邻；岛**保留真实地理位置**（挪开一千公里会让几何碰不到） |
| 岛省照样会被埋住的伙伴卡住 | 单出口省份落单 | 「窄路」单省方块等伙伴落地再发牌（`canDeal`） |
| **第 29 块（共 30 块）投下就发全投放奖励并开始倒计时** | 发牌是**提前两张**的（`current` + `next`），所以「牌堆空」比「最后一块投放完」早一手 | 判据改成 `!deck.length && !next` |

最后一条值得说明：`drop()` 原本写的是 `if (!deck.length)` 当作"最后一块投完了"。但开局牌堆只有
`PIECE_COUNT - 2` 张（两张已经抽在手上和预位上），所以在第 29 块投下时牌堆就空了，而第 30 块
正躺在 `next` 里。结果就是**提前一块**发 +1,000 奖励、提前一块开始 16 秒倒计时（等价于少给一块的时间）。
`tools/diag-dealcount.mjs` 会把整局的牌堆剩余、已投放块数、倒计时状态逐块打出来，一眼能看到在第几块触发。
